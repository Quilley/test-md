Reading a small system.

A set of editorial patterns for explaining a mechanism, keeping assumptions visible, and showing what a simple calculation does and does not establish.

01

The path sets the output.

Margin note

Capacity describes a sustained rate here. It does not predict the wait for any one customer.

If six orders enter each minute and four can be completed, unfinished work grows by two orders per minute. That arithmetic follows from the inputs. It does not identify where the queue forms or how long anyone waits.

Follow the work to the point where it is complete.
02

Keep the boundary in view.

Model note. The rates below are invented to demonstrate the calculation. They are not measurements of a real operation.

Warning. The model assumes steady arrivals, no lost orders and independent steps. Shared staff or counter space could make the second handoff less than twice as capable.

What assumptions make this calculation work?

The path is serial, each step has a fixed capacity, and unfinished work remains available to the next step. Bursts, variation, staffing and customer choices are outside this example.

03

Compare two changes.

Option A · machine upgrade

Raise machine capacity to 12.

Handoff remains at four orders per minute, so completed output stays at four.

Option B · second handoff

Test capacity of eight.

If the added position operates independently, path capacity rises above the six incoming orders per minute.

Sources and method.

This page contains no external empirical source. All values are constructed for the example, and all conclusions are conditional on the stated assumptions.

path_capacity = min(machine, handoff)

1. In a serial path with fixed capacities, sustained path capacity is the smaller step capacity: min(machine, handoff). Under the current inputs, min(8, 4) = 4 orders per minute.
