Sizing

What it costs to run 10,000 agents.

Every figure here is drawn from data in the source. All numbers are invented for the example.

Memory sets the ceiling.

Each node can run 64 agents on its processors and 54 on its network link, but only 30 before memory runs out. Adding processors changes nothing until memory moves.

A change in memory design lifts the ceiling.

Right-sizing the memory each agent keeps raises the memory limit from 30 to 46. The processor and network limits are untouched, so the gain is real up to 54 agents.

The bill is a range, not a number.

Running 10,000 agents costs $41 thousand a month at the median assumption, and between $29 and $77 thousand across the cases we tried. The spread sits mostly in memory nodes and support.

Where the three cases differ.

The three cases share the same compute, but the high case spends far more on memory nodes and on other costs. Seeing the parts stacked shows which part makes the high case.

Cost climbs with the number of agents.

Cost grows roughly in proportion to agents under every case. The cases fan out as the fleet grows, so an error in an assumption costs more at 10,000 than at 2,000.

Memory per agent moves the answer most.

Each bar changes one assumption and holds the rest at the base case. The wider the bar, the more that assumption matters.

Four changes take the bill from $77 to $41 thousand.

Starting from the high case, each change removes a share. Right-sizing memory is the largest, and cutting idle support and storage is next.

Every part falls, memory furthest.

Comparing each part before and after shows the same four changes by part. Memory nodes fall from $38 to $21 thousand and support from $15 to $3 thousand.

Test the uncertain, high-impact assumptions first.

Impact is the swing from the sensitivity chart. Uncertainty is how sure we are of the value, from 1 to 10. The top right is where a test pays for itself.
